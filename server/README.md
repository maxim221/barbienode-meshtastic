# Сервисы Orange Pi

Серверные компоненты используют общее виртуальное окружение с Python-клиентом
Meshtastic; MQTT-чат дополнительно использует `paho-mqtt`.

- `web_server.py` — статический SPA-сервер, allowlist reverse proxy к плате,
  локальные API NodeDB, наведения, расписания Ping и отдельного MQTT-чата.
- `link_quality_collector.py` — пассивный суточный журнал качества RF, исполнитель
  автоматических Ping и локальный TCP-шлюз ручной отправки. Шлюз слушает только
  `127.0.0.1:8765`; браузер обращается к нему через `/lora-send.json` веб-сервера.
- `node_health_monitor.py` — пассивно опрашивает локальный `/json/report` раз в
  минуту и сохраняет раз в пять минут аптайм, счётчик перезагрузок, Wi-Fi RSSI,
  загрузку эфира и доступную энерготелеметрию. Переходы `up`/`down` и обнаруженные
  перезагрузки записываются сразу. Проверка `/status` отличает работающий
  MeshCore/RNode от настоящей потери питания; LoRa-пакеты монитор не создаёт.
- `nightbot_archive.py` — сбор JSONL в SQLite и локальная страница экспорта.
- `meshcore_bridge.py` — локальный TCP-клиент MeshCore, архив каналов и личных
  сообщений и API на `127.0.0.1:8766`. Он не использует MQTT, не запускает
  периодические advert и не возвращает ключи каналов браузеру.
- `meshcore_pair.py` — одноразовое создание BlueZ bond с явно заданным адресом
  companion-ноды до чтения защищённых GATT-сервисов; PIN не журналируется.
- `reticulum_bridge.py` — сохранённый переходный LXMF-мост. В постоянной
  установке его заменяет официальный headless MeshChatX: один процесс на
  Orange Pi владеет RNode, identity, контактами и историей.
- `rnode_mode_control.py` — узкий loopback-helper: перед удалённым переходом в
  Meshtastic останавливает MeshChatX, освобождает TCP-сеанс RNode и затем
  возвращает службу для ожидания следующей загрузки RNode.
- `systemd/barbienode-combo-bluetooth.service` — сохраняет питание общего
  RF-тракта RTL8723BU, оставляя Wi-Fi-интерфейсы выключенными и без IP.
- `systemd/` — sandboxed unit-файлы с общей конфигурацией
  `/etc/barbienode/barbienode.env`.

Проверка без установки:

```bash
python3 -m py_compile web_server.py link_quality_collector.py node_health_monitor.py nightbot_archive.py
```

Unit веб-сервера использует `StateDirectory=barbienode-web`, поэтому снимок
NodeDB переживает перезапуск службы и обновление статических файлов. Размер
принимаемого JSON ограничен 4 MiB, число нод — 2000; запись выполняется атомарно.

Ручные сообщения, Ping, запрос позиции и трассировка проходят через постоянное
TCP-соединение коллектора. Это исключает ложный успех браузерного HTTP-транспорта,
когда packet ID был создан локально, но пакет не попадал в радиоочередь. Точный
текст `Ping` шлюз разрешает только широковещательно в активном канале с точным
именем `Ping`.

MeshCore-мост устанавливается в отдельное окружение, чтобы его зависимости не
меняли Meshtastic-сервисы:

```bash
python3 -m venv /opt/barbienode-meshcore/venv
/opt/barbienode-meshcore/venv/bin/pip install -r requirements-meshcore.txt
```

Веб-мессенджер разделяет каналы и личные диалоги, позволяет отвечать без
пересылки цитаты (в канале добавляется только `@[имя]`) и добавлять каналы в
свободные слоты. Перед каждой записью канала мост
сохраняет полный снимок прежних имён и ключей в защищённом каталоге
`/var/lib/barbienode-meshcore/channel-backups` с правами `0700/0600`; ключи не
возвращаются браузеру и не попадают в журнал сообщений.

Orange Pi подключается к companion-ноде по локальному TCP на порту `5000`.
Прошивка принимает этот протокол только с адреса `192.168.1.19`, поскольку сам
MeshCore TCP не аутентифицирует клиента. При первом успешном
подключении мост принимает только имя с префиксом `BarbieNode` и сохраняет
публичный ключ ноды с правами `0600`; последующие подключения обязаны совпасть
с этим ключом. BLE остаётся свободным для нативного приложения телефона.
Одновременное пассивное чтение допустимо, но не следует параллельно отправлять
команды или менять настройки с телефона и веб-сервера.
Локальная device-query каждые 10 секунд служит только проверкой TCP-сокета и
не создаёт пакет LoRa. Благодаря ей после потери питания ноды мост отбрасывает
устаревшее состояние соединения и переподключается автоматически.

Встроенный MeshCore Ping-бот по умолчанию выключен и включается только через
локальный API/UI после явного решения пользователя. Он реагирует исключительно
на точный текст `Ping`: в личном сообщении отвечает тому же контакту, а в
канале — только в `#ping` и только в этот же канал. Состояние дедупликации и
лимитов хранится с правами `0600`: не чаще одного ответа отправителю за 5 минут
и не более 10 ответов суммарно за час. Периодических сообщений, advert или
ответов в `Public` бот не создаёт.

Для временной диагностики с Linux-станции unit-файлы из `systemd-user/`
запускают BLE-вариант моста на `127.0.0.1:18766` и веб-мессенджер на
`127.0.0.1:8083`. Постоянный Orange Pi использует TCP. Временные службы не
открывают порты в локальную сеть и не передают advert или сообщения без явного
действия пользователя в интерфейсе.

MeshChatX/Reticulum устанавливаются в отдельное окружение:

```bash
python3 -m venv /opt/barbienode-meshchatx/venv
/opt/barbienode-meshchatx/venv/bin/pip install reticulum-meshchatx==4.9.3
```

Рабочая конфигурация лежит в `/var/lib/barbienode-meshchatx`: только
`RNodeInterface` к `192.168.1.31`, без публичных TCP-хабов и интернет-шлюзов.
Web UI слушает HTTPS на `192.168.1.19:9337`, требует локальный пароль и не
публикуется в Интернет. Радиопрофиль — `868.825 MHz`, `BW 125 kHz`, `SF10`,
`CR 4/7`, `18 dBm`. Состояние `sent`/`queued` не выдаётся за подтверждённую
доставку адресату.
Перед возвратом в Meshtastic интерфейс сначала освобождает TCP-сеанс RNode;
служба затем перезапускается и ждёт следующей загрузки RNode. Это действие не
формирует LXMF-пакет и не является передачей пользовательских данных в эфир.
Локальный propagation-узел сохраняется в той же серверной базе. Автоанонсы,
автовыбор внешнего propagation-узла, периодическая LoRa-синхронизация и
автоповтор старых неудачных сообщений выключены. При Meshtastic или MeshCore
MeshChatX остаётся запущен, показывает RNode offline и возобновляет приём после
возврата прошивки RNode. Десктопный MeshChatX и его старый sync-timer отключены:
все компьютеры и телефоны используют один браузерный интерфейс Orange Pi.
