# BarbieNode Meshtastic

Локальная, независимая от Интернета система для Meshtastic на базе
ESP32-S3 + E22-900M22S и постоянно включённого Orange Pi.

Проект вырос из домашнего узла, которому нужны были три режима работы:

- дома — открыть знакомый интерфейс с любого устройства в локальной сети;
- в дороге — подключиться телефоном прямо к точке доступа платы;
- круглосуточно — сохранять принятые сообщения на Orange Pi, даже когда
  рабочий компьютер выключен.

Здесь опубликованы исходники. Пароли Wi-Fi, ключи каналов, координаты,
экспорты конфигурации, журналы реальных сообщений и готовые бинарники в
репозиторий намеренно не входят.

## Что получилось

```mermaid
flowchart LR
    L[LoRa 868 МГц] <--> E[ESP32-S3 + E22]
    P[Телефон] -->|домашний Wi-Fi| O[Orange Pi]
    O -->|HTTP proxy| E
    O -->|раз в минуту| A[(SQLite архив)]
    P -. без роутера .->|BarbieNode-Portable| E
```

- Компактный русскоязычный интерфейс: сообщения, узлы, офлайн-карта,
  диагностика эфира, настройки и переключение Meshtastic/RNode.
- Веб-приложение работает локально. Для основных функций Интернет не нужен.
- Orange Pi раздаёт тот же интерфейс и проксирует API платы, поэтому ноутбук
  можно выключить.
- Если домашняя сеть недоступна 60 секунд, прошивка поднимает защищённую точку
  `BarbieNode-Portable` на `http://192.168.4.1`.
- Сообщения из двух кольцевых JSONL-журналов платы собираются в SQLite.
- Meshtastic находится в `app0`, RNode — в `app1`; переключение всегда
  сопровождается перезагрузкой.
- Точный `Ping` на одноимённом канале получает ограниченный по частоте `Pong`
  с числом входящих ретрансляций, RSSI и SNR.
- Светодиод кратко показывает непрочитанные сообщения: зелёный — нет,
  синий — канал, красный — личное, белый — оба типа.

## Состав репозитория

- `web/` — Vite-приложение поверх зафиксированной версии Meshtastic Web.
- `firmware/` — вариант платы и накладываемые на Meshtastic firmware изменения.
- `server/` — минимальный HTTP-прокси, архиватор и unit-файлы systemd.
- `docs/` — схема работы, сборка, установка и ограничения безопасности.

Для повторения аппаратной части используйте [подробную инструкцию по
распайке](docs/wiring.md): в ней есть ориентация обеих плат, номера площадок
E22, питание, конденсаторы, порядок пайки, контроль мультиметром и диагностика.

## Быстрый старт

Сначала прочитайте [инструкцию по безопасности](docs/safety.md). Особенно
важно: не включайте передачу без подходящей антенны и не прошивайте стандартный
Meshtastic OTA-образ в `app1` — там находится RNode.

### Веб-интерфейс

```bash
cd web
docker build --output type=local,dest=dist .
python3 ../server/web_server.py
```

По умолчанию сервер слушает порт `8082` и обращается к
`http://meshtastic.local`. Настройка выполняется переменными окружения:

```bash
DEVICE_URL=http://192.168.1.31 BIND_HOST=127.0.0.1 PORT=8082 \
  WEB_ROOT="$PWD/dist" python3 ../server/web_server.py
```

### Прошивка

Код рассчитан на Meshtastic firmware commit
`608ff51c867da2004178f8c281397ffbc5079f6e`.

```bash
git clone --recursive https://github.com/meshtastic/firmware.git meshtastic-firmware
git -C meshtastic-firmware checkout 608ff51c867da2004178f8c281397ffbc5079f6e
python3 ./firmware/apply-dualboot.py "$(pwd)/meshtastic-firmware"
cd meshtastic-firmware
pio run -e e22-s3-n16r8
```

Подробности: [распайка](docs/wiring.md), [сборка прошивки](docs/firmware.md) и
[установка на Orange Pi](docs/orange-pi.md).

## Автономность

Orange Pi нужен для постоянного LAN-адреса и долговременного архива, но не для
работы самой платы. При отсутствии домашней сети телефон подключается напрямую
к защищённой точке платы. Конфигурация каналов, LoRa-приём/передача и короткий
архив продолжают работать локально.

Единственная внешняя ссылка в интерфейсе — необязательное открытие координат в
OpenStreetMap. Сама карта относительная и не загружает тайлы.
