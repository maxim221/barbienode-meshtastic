# Веб-интерфейс

Сборка заменяет embedded-приложение зафиксированной версии Meshtastic Web на
компактный интерфейс BarbieNode. Dockerfile клонирует upstream, применяет
небольшой патч SDK и выдаёт обычные и gzip-файлы в `dist/`.

```bash
docker build --output type=local,dest=dist .
```

`app/public/node-location.json` намеренно пуст. Для локальной фиксированной
точки укажите координаты и node ID только в развёрнутой копии. Поле
`shareOverLoRa` является документирующим: интерфейс сам не публикует эту точку
в радиоэфир.

Статические файлы можно загрузить в LittleFS платы или раздавать через
`server/web_server.py`. Второй вариант удобнее для Orange Pi и не требует
перепрошивки при изменении интерфейса.

Вкладка **Настройки** содержит локальный редактор всех восьми слотов каналов:
можно добавлять и отключать вторичные каналы, менять имя, PSK, точность позиции,
mute, AEAD и MQTT-направления. Основной канал нельзя удалить через этот
редактор. PSK скрыт и не попадает в DOM как текст; пустое поле сохраняет
текущий ключ. Перед каждым изменением автоматически скачивается полная
резервная копия конфигурации, которую следует хранить как секрет.

Перед личной отправкой интерфейс проверяет, есть ли в принятом NodeInfo
32-байтный публичный ключ получателя. Если ключа нет, отправка блокируется до
эфира с объяснением ошибки `PKI_SEND_FAIL_PUBLIC_KEY` (`39`) и вариантами:
дождаться свежего NodeInfo либо вернуться в общий канал. Ответ на архивное или
адресованное другой ноде сообщение дополнительно помечается предупреждением.
Ошибки маршрутизации показываются с причиной и следующим безопасным действием.

Последний безопасный снимок NodeDB сохраняется через Orange Pi в
`/var/lib/barbienode-web/node-cache.json`. При следующем открытии знакомые ноды
показываются сразу, а полная конфигурация ESP32 загружается в фоне. Начальный
поток NodeInfo применяется одной пачкой, поэтому сотни нод не вызывают сотни
полных перерисовок списка. В снимок не входят ключи каналов, Wi-Fi-пароли,
закрытые или публичные ключи нод. Личная отправка разблокируется только после
получения свежего публичного ключа непосредственно от ESP32.

Вкладка **Эфир** сохраняет для новых пакетов `hopStart`, `hopLimit` и
однобайтовый `relayNode`. В свойствах показываются число переходов и путь от
источника через последний известный ретранслятор к BarbieNode. Совпадение
`relayNode` с полной записью NodeDB считается кандидатом: один байт ID может
совпасть у нескольких нод.

Вкладка **Наведение** хранит локальную точку, сравнивает прямые RF-пакеты по
азимутам, показывает направления до нод с 0–2 переходами и ведёт контрольные
замеры. Автоматический Ping выполняется Orange Pi с заданными интервалом и
количеством. Ответы сопоставляются с нашей нодой по полному ID, четырём последним
цифрам ID и известным именам; для каждого Ping показываются нода, время и задержка.

Ручные сообщения, Ping, запрос позиции и трассировка отправляются через локальный
TCP-шлюз Orange Pi. Ответ позиции и результат трассировки отображаются раздельно,
поскольку обычный пакет позиции не является ответом трассировки.

Кнопка **Фото** в редакторе открывает `meshpic.org` в новой вкладке. Изображение
загружается туда через Интернет самим пользователем; в сообщение Meshtastic
вставляется и по LoRa отправляется только скопированная короткая ссылка.

Вкладка **MQTT** использует отдельный журнал и не смешивает интернет-сообщения с
LoRa. Профиль можно выбрать из списка или заполнить вручную; MQTT по умолчанию
остаётся выключенным. Пакет, пришедший обратно через реальный LoRa-приёмник,
отображается в обычном радиоархиве как LoRa.
